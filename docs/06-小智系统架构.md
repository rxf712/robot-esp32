# 小智系统架构

> 基于 robot-esp32 v2.2.6，目标板型：camera-xiaozhi（ESP32-S3）

---

## 1. 总体分层

```
┌──────────────────────────────────────────────────────────────────┐
│                        应用层 (Application)                       │
│  main.cc → Application::Initialize() → Application::Run()        │
│  主事件循环，FreeRTOS 事件组驱动，状态机管理设备全局状态              │
├──────────────────────────────────────────────────────────────────┤
│                       业务模块层                                   │
│   AudioService │ Protocol (WS/MQTT) │ OTA │ McpServer │ Settings  │
├──────────────────────────────────────────────────────────────────┤
│                       板级抽象层 (Board)                           │
│   Board → WifiBoard → CameraXiaozhiBoard                          │
│   提供：AudioCodec / Display / Led / Backlight / Camera / Battery  │
├──────────────────────────────────────────────────────────────────┤
│                       硬件驱动层                                   │
│   ESP-IDF 驱动：I2C / SPI / I2S / ADC / Camera / LEDC             │
│   芯片：ST7789 / ES8311 / ES7210 / GC0308 / PCA9557 / NS4150B     │
└──────────────────────────────────────────────────────────────────┘
```

---

## 2. 入口与主循环

| 文件 | 职责 |
|------|------|
| `main/main.cc` | `app_main()`：初始化 NVS Flash，创建 Application 单例，调用 `Initialize()` + `Run()` |
| `main/application.cc` | 主事件循环（永不返回），FreeRTOS 事件组驱动，处理网络、音频、用户输入 |
| `main/device_state_machine.cc` | 设备状态机，管理 `DeviceState` 枚举的合法转换 |

### DeviceState 状态枚举

```
kDeviceStateStarting      → 上电初始化
kDeviceStateWifiConfiguring → 配网模式（BluFi / SmartConfig）
kDeviceStateIdle          → 空闲，等待唤醒
kDeviceStateConnecting    → 连接服务器中
kDeviceStateListening     → 录音中
kDeviceStateSpeaking      → 播放回复中
kDeviceStateUpgrading     → OTA 升级中
kDeviceStateActivating    → 设备激活中
kDeviceStateAudioTesting  → 音频自检
kDeviceStateFatalError    → 不可恢复错误
```

## 3. 音频子系统

```
麦克风(ES7210)
    │
    ▼
[AudioCodec::Read(PCM)]
    │
    ▼
[AudioProcessor]  ←── AFE (ESP-SR 算法: AEC + NS + VAD)
    │                  或 NoAudioProcessor（无处理）
    ▼
[WakeWord 检测]   ←── esp_wake_word / afe_wake_word / custom_wake_word
    │
    ▼
[Opus 编码器]    OPUS_FRAME_DURATION_MS = 60ms
    │
    ▼
[SendQueue] ──→ Protocol::SendAudio() ──→ 服务器

服务器回复
    │
    ▼
[DecodeQueue] ←── Protocol::OnAudioData()
    │
    ▼
[Opus 解码器]
    │
    ▼
[PlaybackQueue]
    │
    ▼
[AudioCodec::Write(PCM)] ──→ 扬声器(ES8311 + NS4150B)
```

**音频编解码实现**（`main/audio/codecs/`）：

| 类 | 用途 |
|----|------|
| `BoxAudioCodec` | ES7210（ADC 多麦输入）+ ES8311（DAC 输出），本板使用 |
| `Es8311AudioCodec` | 单 Codec，无 ES7210 |
| `Es8388AudioCodec` | 另一款 Codec 方案 |
| `DummyAudioCodec` | 纯软件测试，无硬件 |

**AEC 模式**（回声消除）：

| 模式 | 说明 |
|------|------|
| `kAecOff` | 关闭 |
| `kAecOnDeviceSide` | 端侧 AEC（AFE 算法，本板默认，`CONFIG_USE_DEVICE_AEC=y`）|
| `kAecOnServerSide` | 云端 AEC |

## 4. 网络与协议

```
WifiBoard
    ├── WiFi 连接管理（ESP-IDF wifi_manager）
    ├── BluFi 配网（blufi.cpp）
    └── NetworkEvent 回调 → Application
            │
            ├── WebSocketProtocol（双向音频 + JSON 控制）
            └── MqttProtocol（轻量控制通道）
```

**BinaryProtocol2 / BinaryProtocol3**：音频流二进制帧格式，携带 timestamp 用于服务端 AEC 对齐。

**OTA 流程**（`main/ota.cc`）：
1. `CheckVersion()` → HTTPS 请求检查版本 + 获取 MQTT/WebSocket 配置
2. 设备激活（`Activate()`）→ 首次联网时获取激活码
3. `StartUpgrade()` → HTTP 分块写入 OTA 分区（`ota_0` / `ota_1` 交替）
4. `MarkCurrentVersionValid()` → 写 otadata，确认启动分区

## 5. 板级抽象层

### 继承链

```
Board  (board.h)
  └── WifiBoard  (wifi_board.h)
        └── CameraXiaozhiBoard  (camera_xiaozhi_board.cc)
```

### Board 提供的接口

| 接口 | 说明 |
|------|------|
| `GetAudioCodec()` | 返回音频编解码实例 |
| `GetDisplay()` | 返回显示实例 |
| `GetLed()` | 返回 LED 实例（WS2812 / GPIO LED） |
| `GetBacklight()` | 返回背光控制实例 |
| `GetCamera()` | 返回摄像头实例 |
| `GetBatteryLevel()` | 返回电量 / 充电状态 |
| `GetTemperature()` | 返回 ESP32 内部温度 |
| `StartNetwork()` | 异步启动网络连接 |
| `EnterWifiConfigMode()` | 进入 BluFi 配网模式 |

### CameraXiaozhiBoard 板级资源初始化顺序

```
CameraXiaozhiBoard()
  1. InitializeI2c()       ← I2C bus port1，SDA=GPIO1，SCL=GPIO2
                              + PCA9557(0x19) 初始化
  2. InitializeSpi()       ← SPI3_HOST，MOSI=GPIO40，SCK=GPIO41
  3. InitializeSt7789Display() ← ST7789，DC=GPIO39，BL=GPIO42
                                  支持横竖屏切换（NVS lcd_display/lcd_mode）
  4. InitializeButtons()   ← BOOT(GPIO0) / 音量+(GPIO3) / 音量-(GPIO46)
  5. InitializeCamera()    ← GC0308 DVP，XCLK=GPIO17，FRAMESIZE_VGA
  6. InitializeTools()     ← 注册 MCP 工具（reconfigure_wifi）
  7. GetBacklight()->RestoreBrightness()
```

## 6. 显示子系统

| 类 | 说明 |
|----|------|
| `SpiLcdDisplay` | 通用 SPI LCD（基于 esp_lcd 组件），本板使用 |
| `EmoteDisplay` | 带表情动画（`CONFIG_USE_EMOTE_MESSAGE_STYLE=y` 时启用）|
| `OledDisplay` | SSD1306/SSD1315 等 OLED |

**横竖屏配置**（NVS `lcd_display/lcd_mode`）：

| 值 | 方向 | 分辨率 |
|----|------|--------|
| 1（默认） | 横屏 | 320×240 |
| 0 | 竖屏 | 240×320 |

---

## 7. MCP Server（模型控制协议）

`McpServer` 提供工具注册机制，允许云端大模型在对话中调用设备端功能：

| 工具 | 功能 |
|------|------|
| `self.system.reconfigure_wifi` | 触发重新配网（本板已注册）|
| 其他工具 | 各板型可在 `InitializeTools()` 中扩展注册 |

工具通过 WebSocket 协议透传 JSON，服务器决策后下发调用指令。

## 8. 持久化存储（NVS）

| Namespace | Key | 内容 |
|-----------|-----|------|
| `wifi` | `ssid` / `password` | WiFi 凭据 |
| `lcd_display` | `lcd_mode` | 横/竖屏模式（0=竖，1=横）|
| `boot_config` | `is_first` | 首次启动标志（用于双击 BOOT 逻辑）|

## 9. 分区表（16MB Flash）

分区表文件：`partitions/v2/16m.csv`

| 分区名 | 类型 | 偏移地址 | 大小 | 说明 |
|--------|------|----------|------|------|
| `nvs` | data/nvs | `0x9000` | 16 KB | WiFi 凭据、设置、LCD 模式等 |
| `otadata` | data/ota | `0xd000` | 8 KB | OTA 启动分区选择标志 |
| `phy_init` | data/phy | `0xf000` | 4 KB | RF 校准数据 |
| `ota_0` | app/ota_0 | `0x20000` | 4 MB | 主应用固件（当前运行）|
| `ota_1` | app/ota_1 | `0x420000` | 4 MB | OTA 备用分区（升级写入）|
| `assets` | data/spiffs | `0x800000` | 8 MB | 静态资源（UI 图片、音频等）|

### 烧写地址对照

| 文件 | 烧写地址 | 说明 |
|------|----------|------|
| `build/bootloader/bootloader.bin` | `0x0` | 一级引导 |
| `build/partition_table/partition-table.bin` | `0x8000` | 分区表 |
| `build/ota_data_initial.bin` | `0xd000` | OTA 启动选择（初始化为 ota_0）|
| `build/xiaozhi.bin` | `0x20000` | 应用固件（ota_0）|
| `build/generated_assets.bin` | `0x800000` | 静态资源 |

**NVS 分区（`0x9000`）不在烧写列表中，WiFi 配置等数据不会被覆盖。**

## 10. 构建与发布

```bash
# 推荐方式（自动处理 sdkconfig + 构建 + 打包）
python scripts/release.py camera-xiaozhi

# 输出：releases/v2.2.6_camera-xiaozhi.zip
```

`release.py` 内部流程：
1. `idf.py set-target esp32s3`
2. 追加 `CONFIG_BOARD_TYPE_CAMERA_XIAOZHI=y`、`CONFIG_USE_DEVICE_AEC=y` 到 sdkconfig
3. `idf.py build`
4. 打包所有 `.bin` 文件 + flash 脚本为 zip

### 手动烧写命令

```bash
python -m esptool --chip esp32s3 -b 460800 \
  --before default_reset --after hard_reset \
  write_flash --flash_mode dio --flash_size 16MB --flash_freq 80m \
  0x0      build/bootloader/bootloader.bin \
  0x8000   build/partition_table/partition-table.bin \
  0xd000   build/ota_data_initial.bin \
  0x20000  build/xiaozhi.bin \
  0x800000 build/generated_assets.bin
```
