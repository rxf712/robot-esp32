# 硬件映射与参考板分析

## 2026-04-21 基于原理图的第一版结构化整理

### 1. 文档目的

本文档用于将 [原理图.pdf](./%E5%8E%9F%E7%90%86%E5%9B%BE.pdf) 中可确认的信息整理为结构化输入，作为后续：

- 新板型目录创建
- `config.h` 引脚定义
- `config.json` 构建配置
- 板级驱动适配
- 实机 Bring-up 清单

的直接依据。

### 2. 总体判断

当前硬件不是纯语音对话板，而是带摄像头、LCD、双麦、功放、电池充电和状态检测的复合型 ESP32-S3 设备。

根据 2026-04-21 的新增确认资料：

- LCD 驱动芯片：`ST7789`
- 摄像头模组：`GC0308`
- 软件引脚基线：可按 `lichuang-dev` 处理或近似处理

从“功能拓扑”角度看，最接近的参考实现主要有两类：

- `main/boards/zhengchen-cam/`
- `main/boards/lichuang-dev/`

其中：

- `zhengchen-cam` 更接近原理图抽取出来的外围连接关系
- `lichuang-dev` 与用户最新确认的 `ST7789 + GC0308 + 相近引脚` 更适合作为当前代码落地基线

原因：

- 同为 `ESP32-S3 + 16MB Flash + 8MB PSRAM`
- 同时具备 `DVP Camera + LCD + ES7210 + ES8311 + 功放`
- `lichuang-dev` 已使用 `ST7789 + GC0308`
- I2S/I2C 主音频引脚与本板高度一致
- LCD SPI 主引脚与本板一致
- 也使用 `PCA9557` 作为 IO 扩展

### 5. I2C 总线

| 信号 | 引脚 |
| --- | --- |
| I2C SDA | GPIO1 |
| I2C SCL | GPIO2 |

I2C 挂载器件：

- `PCA9557`，地址 `0x19`
- `ES7210`，标注地址 `0x41`
- `ES8311`，标注地址 `0x18`
- DVP 摄像头 SCCB/I2C

注：

- 软件实现时，需注意部分现有代码中对 `ES7210` 地址使用的是左移后的 8-bit 地址写法。

### 6. IO 扩展 PCA9557

PCA9557 地址：`0x19`

| PCA9557 IO | 连接信号 | 说明 |
| --- | --- | --- |
| IO0 | `LCD_CS` | LCD 片选 |
| IO1 | `PA_EN` | 功放使能 |
| IO2 | `DVP_PWDN` | 摄像头掉电控制 |
| IO7 | `RESET#` | 外设复位控制 |

当前从原理图可见 IO3~IO6 未明确使用。

### 7. LCD / TFT 接口

从页 2 的 TFT 接口可确认这是 SPI 屏接口，主控侧信号如下：

| 信号 | 引脚 |
| --- | --- |
| LCD DC | GPIO39 |
| LCD MOSI | GPIO40 |
| LCD SCK | GPIO41 |
| LCD BL | GPIO42 |
| LCD CS | PCA9557 IO0 |
| LCD RESET | `RESET#` / PCA9557 IO7 |

补充判断：

- 屏驱动芯片现已确认是 `ST7789`。
- 分辨率当前仍先按 `lichuang-dev` 的 `320x240` 软件基线处理，待实机确认。

#### 9.3 麦克风

原理图显示至少两路模拟麦接入：

- `ADC_MIC1P / ADC_MIC1N`
- `ADC_MIC2P / ADC_MIC2N`

同时 ES7210 还保留 `MIC3` 通道网络。是否最终启用到软件采集，需结合板载器件数量和现有驱动配置确认。

### 11. 与现有参考板差异

对比 `zhengchen-cam`：

相同点：

- 音频引脚一致：`MCLK=38 / BCLK=14 / WS=13 / DI=12 / DO=45`
- I2C 一致：`SDA=1 / SCL=2`
- LCD 主引脚一致：`DC=39 / MOSI=40 / SCK=41 / BL=42`
- 使用 `PCA9557` 控制 `LCD_CS / PA_EN / DVP_PWDN`
- 芯片资源等级一致：`ESP32-S3 + 16MB Flash + 8MB PSRAM`

差异点：

- 经供应商 config.h 与原理图核对，**摄像头引脚与 `zhengchen-cam` 完全一致**，无差异。
- 本板明确有 `GPIO47` VBUS 充电检测、`GPIO10` 电池电压 ADC 检测。
- 本板三个按键：BOOT(GPIO0) / 音量+(GPIO3) / 音量-(GPIO46)。

对比 `lichuang-dev`：

相同点：

- 已确认使用 `ST7789 + GC0308`
- 音频链路一致：`ES7210 + ES8311 + NS4150B`
- I2C/I2S/LCD 主引脚布局与当前项目目标一致或近似
- 同样使用 `PCA9557`

当前结论：

- 本项目编码阶段优先按 `lichuang-dev` 落地最稳妥。

### 12. 推荐实施策略

#### 12.1 软件参考基线

优先以 `lichuang-dev` 作为当前编码基线进行新板型适配。

理由：

- 用户已明确确认 `ST7789 + GC0308 + lichuang-dev 近似引脚`。
- 可以最大限度复用 `Pca9557 + BoxAudioCodec + Camera + ST7789` 的适配思路。
- 能明显降低 bring-up 风险。

#### 12.2 建议的新板型实施顺序

1. 先复制 `zhengchen-cam` 的板级实现思路建立新目录。
2. 先仅调整 `config.h` 中已确认的音频、LCD、PCA9557 和电源检测引脚。
3. 摄像头部分按当前原理图重新映射。
4. `GPIO3` 冲突在实物验证前保持显式注释，必要时先关闭对应按键功能。
5. 屏驱动先按 `ST7789` 尝试，若初始化异常再回到屏幕丝印确认。

### 14. 当前结论

- 当前原理图已经足够支持进入“新板型骨架创建”阶段。
- 最佳参考板是 `zhengchen-cam`，而不是普通语音板。
- 后续编码阶段应优先解决摄像头引脚差异和 `GPIO3` 复用问题。
