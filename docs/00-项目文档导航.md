# 项目文档导航

本文档用于说明当前 fork 工程在“新硬件移植”和“交互优化”两个阶段下的文档组织方式，便于后续开发、测试、交付和回溯。

## 文档列表

- [01-需求文档.md](./01-%E9%9C%80%E6%B1%82%E6%96%87%E6%A1%A3.md)：记录需求背景、目标、范围、验收标准和资料缺口。
- [02-方案文档.md](./02-%E6%96%B9%E6%A1%88%E6%96%87%E6%A1%A3.md)：记录系统架构、板级适配方案、接口边界、模块关系和核心时序。
- [03-开发文档.md](./03-%E5%BC%80%E5%8F%91%E6%96%87%E6%A1%A3.md)：记录当前实现状态、开发分解、风险与未完成项。
- [04-交付文档.md](./04-%E4%BA%A4%E4%BB%98%E6%96%87%E6%A1%A3.md)：记录构建、烧录、配置、验证、发布和回滚流程。
- [05-硬件映射与参考板分析.md](./05-%E7%A1%AC%E4%BB%B6%E6%98%A0%E5%B0%84%E4%B8%8E%E5%8F%82%E8%80%83%E6%9D%BF%E5%88%86%E6%9E%90.md)：记录从原理图提取的硬件资源、引脚映射和参考板建议。
- [原理图.pdf](./%E5%8E%9F%E7%90%86%E5%9B%BE.pdf)：当前硬件原理图输入资料。

## 文档使用原则

- 项目进入新阶段时，先更新 `01-需求文档.md`，再更新 `02-方案文档.md`。
- 进入编码前，必须完成目标板硬件资源确认，包括芯片、Flash/PSRAM、显示、音频、按键、灯效、电源和通信方式。
- 每次产生实质开发动作后，同步更新 `03-开发文档.md` 和 `04-交付文档.md`。
- 当前硬件资料若只有原理图，没有完整引脚表、BOM、屏幕型号或音频器件型号时，文档中必须保留“待确认项”，禁止直接固化到实现代码。

## 当前项目阶段

- 阶段 1：将小智现有功能稳定移植到当前硬件。
- 阶段 2：在移植稳定基础上，优化交互体验、状态反馈、显示表现和控制流程。

## 推荐后续补充资料

- PCB 原理图导出的引脚分配表。
- 关键器件型号清单：音频编解码器、麦克风、功放、屏幕驱动 IC、触摸 IC、电源管理 IC。
- 目标板实物照片和最小可运行验证记录。
- 量产相关信息：串口下载方式、Flash 分区要求、产测需求。
